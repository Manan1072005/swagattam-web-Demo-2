# Technical handover: GitHub Pages + Supabase export

## PROJECT OVERVIEW

Swagattam Event Estimate Studio is a customer-facing banquet estimator. Customers enter their name, mobile number, event type/date, guest count, bill number, and optional GST details. They choose services grouped by category and subcategory. The UI calculates food-per-plate totals, service totals, GST, grand total, and cost per guest. Customers can print, copy, open a WhatsApp message, or save an itemized estimate. An authenticated operations desk manages the service catalog and reviews saved estimates.

## FINAL ARCHITECTURE

```text
User
  ↓
GitHub Pages (static Vite build)
  ↓
React frontend
  ↓
Supabase Auth + Supabase Postgres REST API
```

There is no runtime server requirement. The browser uses the public Supabase anon key and RLS enforces data access. No service-role key belongs in frontend code.

## SUPABASE SETUP

1. Create a Supabase project.
2. In Project Settings, copy the project URL.
3. Copy the public anon key. Do not copy the service-role key.
4. For local work, copy `.env.example` to `.env.local` and set `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY`.
5. Open Supabase SQL Editor and run `supabase/schema.sql`.
6. Run `supabase/rls.sql`.
7. Run `supabase/seed.sql`.
8. In Authentication, create an email/password user for the operations desk.
9. Add the `role` value `admin` to that user's `app_metadata`. One SQL example is:

   ```sql
   update auth.users
   set raw_app_meta_data =
     jsonb_set(coalesce(raw_app_meta_data, '{}'::jsonb), '{role}', '"admin"', true)
   where email = 'the-admin-email@example.com';
   ```

   Replace the example email with the actual admin account. Do not put this address in frontend code.

10. Start the frontend and open `#/admin`.
11. Sign in with the admin user.
12. Test a catalog update and a customer estimate before publishing.

## DATABASE TABLES

### `catalog`

- `id` — text primary key; the app uses the single row `default`.
- `categories` — JSONB array matching the catalog type in `src/lib/catalog.ts`.
- `updated_at` — UTC timestamp maintained by a database trigger.

Everyone can read the catalog. Only authenticated users whose JWT has `app_metadata.role = 'admin'` can insert or update it. There is no delete operation because the single row is replaced through an upsert.

### `quotes`

- `id` — UUID primary key generated by Postgres.
- `reference` — customer-entered bill number; unique.
- `customer_name`, `mobile`, `event_type`, `event_date`, `guests`, `customer_gst_number`, `hall` — customer and event fields.
- `services` — JSONB itemized selected services.
- `pricing` — JSONB pricing snapshot, including GST settings and totals.
- `status` — `new`, `contacted`, `confirmed`, or `archived`; defaults to `new`.
- `created_at` — UTC creation timestamp.

Anonymous and authenticated visitors can insert a quote after client-side validation. Only an admin can read quotes. The public customer flow receives the inserted record and does not need read access.

No storage bucket is required. The app uses the bundled logo and static assets; it does not upload images or documents.

## RLS POLICIES

- `Public can read catalog` allows `anon` and `authenticated` users to read the active catalog.
- `Admins can insert catalog` and `Admins can update catalog` require `auth.jwt() -> 'app_metadata' ->> 'role' = 'admin'`.
- `Public can submit quotes` permits the public estimate form to insert a quote.
- `Admins can read quotes` limits saved customer data to authenticated admins.

RLS is enabled on both tables. The frontend never receives a service-role credential and cannot bypass these policies.

## AUTHENTICATION

The customer estimator does not require an account. The operations desk at `#/admin` calls Supabase Auth email/password sign-in. Supabase stores and refreshes the browser session. The page listens for auth state changes and signs out through Supabase Auth.

After sign-in, the page checks the user's `app_metadata.role`. A signed-in user without `role = admin` sees an access-denied state and cannot call admin query/mutation paths successfully because the database RLS policies enforce the same rule. Sign-out clears the Supabase session.

## FRONTEND ↔ SUPABASE CONNECTIONS

- Estimator catalog
  → `useGetCatalog()`
  → `public.catalog` row `id = default`
  → active categories and services render in the estimator.

- Save estimate
  → `useCreateQuote()` / `createQuote()`
  → `public.quotes`
  → a saved estimate is shown immediately in the customer summary and can be printed.

- Operations estimate list
  → `useListQuotes({ limit: 12 })`
  → `public.quotes`
  → newest saved briefs appear in the protected operations desk.

- Operations estimate detail
  → `useGetQuote(reference)`
  → `public.quotes`
  → the selected bill opens with customer, services, and pricing details.

- Catalog management
  → `updateCatalog()`
  → `public.catalog`
  → the updated catalog is visible to all visitors after the next query refresh.

When Supabase variables are missing, the estimator shows a clear setup message and uses the built-in catalog as a local fallback. Saving estimates and the operations desk remain unavailable until Supabase is configured.

## DEPLOYMENT TO GITHUB

1. Create a GitHub repository.
2. Upload the project, including `package.json`, `pnpm-workspace.yaml`, `artifacts/`, `supabase/`, `.github/`, and the documentation files.
3. In the repository settings, add Actions repository variables:
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_ANON_KEY`
4. In Settings → Pages, choose **GitHub Actions** as the source.
5. Push to the `main` branch.
6. The workflow installs dependencies, sets `VITE_BASE_PATH` to `/<repository-name>/`, builds the static site, and deploys `artifacts/banquet-estimator/dist/public`.
7. Open the Pages URL. The customer estimator is the default page; use the `#/admin` hash route for operations.
8. For a custom domain, set the workflow's `VITE_BASE_PATH` to `/` and configure the domain in GitHub Pages.

Manual build commands:

```bash
pnpm install
pnpm --filter @workspace/banquet-estimator run build
```

## TROUBLESHOOTING

- **Supabase connection failed:** verify the two `VITE_` variable names and values. Restart the Vite process after changing `.env.local`.
- **RLS policy denied request:** confirm the SQL files ran and that the signed-in user's `app_metadata` contains `{"role":"admin"}`. Do not use `user_metadata` as a substitute; the policy checks app metadata.
- **Catalog is showing the built-in fallback:** the catalog row is missing, Supabase variables are absent, or the catalog query failed. Run `schema.sql`, `rls.sql`, and `seed.sql`, then reload.
- **Images or CSS do not load:** check `VITE_BASE_PATH`. GitHub project sites need `/<repository-name>/`; custom domains need `/`.
- **GitHub Pages blank page:** inspect the Actions build log and confirm `artifacts/banquet-estimator/dist/public/index.html` exists in the uploaded artifact.
- **404 on refresh:** routes intentionally use hash URLs such as `#/admin`, so refresh the hash URL rather than a server path.
- **Auth redirect/session problems:** the app uses email/password auth with a hash route; verify the Supabase Auth provider is enabled and clear stale browser storage before trying again.
- **CORS issues:** use the Supabase project URL, not a local API URL. Add the deployed Pages origin to Supabase Auth URL configuration if email links are later enabled.
- **Environment variables appear empty:** Vite only exposes variables prefixed with `VITE_`, and GitHub Actions variables must be configured before the workflow runs.
